# Communication

Reusable text for the messages the team sends again and again. Each template gives the shape and the tone; the agent fills in the facts. The writing rules in AGENTS.md apply to every word here.

## Channels

- Email from data@answerals.org: access requests, data questions, bug reports, release news to users. This is the default for anything a user or partner will keep.
- Email from a team member's own address: partner outreach and meeting follow-ups, where a person, not the mailbox, owns the relationship.
- DocuSign: the Data Use Agreement only. Never send other content through it.
- The Neuromine portal pages: release notes, the README and public documents. A message points to them; it does not copy them.
- Talks and office hours: program updates and data walkthroughs, built from the outlines in talks/.

## Tone

- Warm, plain and direct. Write the way a helpful colleague talks.
- One ask per message. If there are two asks, send the first and keep the second for the reply.
- No exclamation marks. No praise of the question, no "I hope this finds you well", no closing offer to help more.
- Short paragraphs, two or three sentences each. Bullets only for steps or a list the reader will tick off.
- Say what happened and what has not happened yet. Do not soften a no into a maybe.
- Sign with a first name and the program, for example "[Sender name], Answer ALS data team".

## Response shape

Every message follows the same five parts:

1. Greeting with the person's first name.
2. One line of context: what this message is about.
3. The answer or the ask.
4. The next step, and who takes it.
5. Sign-off with name and program.

## When to escalate

Draft the reply, then hand it to the right role before it goes out when the message:

- decides or hints at an access decision, or touches commercial use: the Data Access Committee.
- says a release is public, gives a release date or quotes a count not on the programs/ pages: the data owner.
- reports a possible privacy problem, such as identifiable information in a file: [Privacy escalation role], the same day.
- interprets DUA terms or any legal question: [Legal escalation role].
- comes from a partner, funder or the press: the program lead.
- names something you do not know. Ask the person who gave the task instead of guessing.

## Never put in a message

- Participant identifiers of any kind: Participant ID, GUID, Subject ID, sample or vial IDs, or counts below the release level.
- SAS strings or any link with a token in it. Link only to the public URLs in answer-als/links/link-registry.csv.
- Internal paths, storage account keys, server names or tool internals.
- Board ticket numbers, sub-release labels (r8.3) or build notes. Users see "Release 8".
- Names of people who did not agree to be named. Use roles.

## Files

- email/: one template per message type. Each has When to use, Subject, Body and Fill in.
- talks/: slide by slide outlines for a program update and a data walkthrough, in the deck layouts from design/README.md.

Fields in square brackets are filled per message. Fields that need a fact the team has not settled yet are listed in NOTES.md.
